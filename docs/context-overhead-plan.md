# Recover bound work with less repeated context

Apply the coordination/overhead feedback generally. Implement three bounded additions: explicit branch/worktree bindings, bounded change-only prompt refreshes, and direct checkpoint summaries. Preserve current staged assessments, exclusive resource claims, atomic outbox/revision checks, authorization and daily completion semantics.

- Bind only explicitly supplied stream/change IDs to an exact branch and canonical worktree. Never parse a ticket prefix, infer a goal from a branch/folder, or modify Git. Manual session selection takes precedence, then a recorded branch association, then the explicit project default. Keep mappings private and credential/client/worktree scoped; helpers and lifecycle hooks resolve the same selection. Changed selection invalidates cached context; delayed writes retain the original selection and conflict normally.
- Full recovery remains at startup/resume/compaction and when startup delivery was missed. Ordinary prompts compare current bounded context with the last delivered snapshot and emit changed sections only. Unchanged receipts retain native turn identity and checkpoint freshness. Include a semantic work fingerprint so changes outside clipped summaries cannot disappear. Never claim a compact/delta refresh is a full dependency review. Retain current assessments only while current.
- Accept a direct checkpoint summary without a temporary JSON file. Explicit progress still requires its exact expected revision; no fetching a newer revision to force a stale write through. Use the same durable outbox, receipt and conflict handling. Do not infer plans, delivery, human answers or claim ownership.

Existing exclusive resources already prevent concurrent cooperative claims for declared resource keys; document their generic use and test that boundary. Existing provider checks stay read-only and milestone-based. Repository-specific shape/deliver commands, issue-provider adapters, alternate MCP tool profiles, runners and proactive wakeups remain separate capabilities; this change does not invoke or emulate them.

Verify branch/session precedence, worktree/client/credential isolation, branch switches, missing Git metadata, deleted/invalid bindings, context change/restart/recovery and selection races, offline replay/stale revisions, and unchanged graph/sync/daily-count behavior. Build/verify an isolated Mac preview; do not install, commit, push or claim real client behavior from helper tests.

## Result and verification

Implemented in unreleased workflow 1.9.0. Branch mappings live in private helper storage; explicit chat overrides and existing project defaults retain their precedence. Invalid Git metadata cannot invent a match, and lease release remains possible without that metadata. Context deltas preserve cursor continuity, native turn identity, full recovery and complete/incomplete distinctions. New decisions, questions/actions, dependency/output changes and observations affect semantic freshness even outside clipped summaries. Older servers without the freshness contract retain ordinary compact refreshes. Direct checkpoint summaries retain exact progress revisions, outbox replay and stale-write conflicts.

On November 20, 175 service/unit/integration tests, 27 browser scenarios, typecheck, formatting, repository-path and source-only secret checks passed. An isolated Mac build and nine packaged verification groups passed, including exact recorded branch selection and direct checkpoint summary submission using the bundled runtime. A final focused 23-test sync pass covered the decision-freshness refinement. Existing exclusive-resource, graph, dependency, interruption, offline/conflict and daily-completion regression coverage remains intact.

Source is uncommitted. The installed app, real project manifest and published installers are unchanged. Real client hook trust/loading and receiving-machine behavior remain separate observations; the preview is ad-hoc signed and not a distribution release. No company host, issue prefix, repository script or provider-specific workflow is embedded.
