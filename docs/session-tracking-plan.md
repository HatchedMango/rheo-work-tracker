# Find the sessions tied to your work

## Goal and first release

Open a stream or change and find the Codex and Claude Code sessions that worked on it, with the latest saved handoff for that work. The user authorized planning and implementation on November 13, 2026.

The existing workflow session is a credential-scoped native identity with a mutable current selection. Retain it for synchronization and add durable per-selection associations. Explicit accepted lifecycle events create/update associations automatically; ordinary MCP context retrieval alone cannot identify a native session and must not invent one.

## Implementation

1. Add a migration for session/work associations, uniquely keyed by workflow session and explicit stream/change selection. Backfill only the currently known selection with its observed event timestamp and saved checkpoint. Earlier lost selections and original creation times cannot be reconstructed.
2. Update associations in the same transaction as accepted lifecycle events/checkpoints. Replays remain idempotent; rejected or delayed events cannot change historical summaries or activity. Switching back updates the existing association and retains its last saved handoff until replaced. Keep existing current-selection synchronization behavior unchanged.
3. Add a bounded, validated read API for an explicit stream or change. Owners see historical sessions even after disconnection; agents see only their credential's sessions. Never return credentials, tokens or transcript contents. Stream lists deduplicate a session across changes and identify its latest related work; change lists use its own saved handoff.
4. Add Sessions sections on stream and change detail views with client, work-derived title, observed activity time, saved summary, project and native identity in expandable details, and pagination. Separate current work selection from recorded activity; neither means a running process or completed work. Derive Codex links only through the existing validated native-thread route. Provide copy-ID fallback for Claude Code and unsupported identities. No shell execution or guessed URLs.
5. Verify switch-away/back history, per-work summaries, replay/stale rejection, credential isolation, pagination, disconnected history, migration/reopen preservation and browser navigation/layout.

## Boundaries and risks

No transcript scanning, session-title scraping, inferred work selection, new execution worker, parking/closeout redesign, Git changes or publication. Titles use the selected work because client titles are not supplied by the lifecycle contract. A generated supported link does not prove that another app still retains the session. Real automatic hook delivery in each native client remains a separate observation from synthetic lifecycle tests. Installed app update is separate from source implementation.
