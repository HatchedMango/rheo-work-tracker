# Keep agent loops in sync

## Implementation plan

Keep Work Inbox as shared memory and a work relationship map. The client or external runner owns execution, continuation, budgets and stopping. This pass does not add a runner or change the work map.

1. Add a short operational loop protocol to shared guidance: recover the selected goal and approach; reuse a change and private claim identity across implement/check/revise iterations; reassess only on relevant drift; checkpoint meaningful results, failed approaches and next steps; distinguish delivery, waiting and interruption. Verify the actual client tool catalog once per session; never substitute legacy evidence for managed readiness.
2. Store lifecycle state per native session with private atomic writes and a cooperative lock. Persist a Stop reminder marker before emitting it, suppress repeats and stop-hook continuations, and preserve the marker across recovery. Add explicit per-session `observe` mode for external runners, alongside default `checkpoint-once`; neither mode emits `continue:false` or controls execution. Preserve old session and selection state when migrating.
3. Keep startup/resume/compaction recovery complete and bounded. Make ordinary prompt injection compact, with current selection, summary, dependency state, questions and explicit full-context retrieval instructions. Do not call a compact view a complete dependency review. Keep pending writes/conflicts visible. Bound interrupt network work within Codex's supported three-second timeout.
4. Test both client contracts, duplicate and concurrent hooks, restart/resume/compaction, runner mode, offline recovery, conflict handling and compatibility. Build/package and verify the native app, back up and update the existing local installation and conflict-aware project guidance. Preserve work, credentials, unrelated client hooks/settings and the project default selection.

## Verification limits

Synthetic hook invocations and packaged MCP SDK checks prove helper/server behavior, not automatic hook delivery or the tool catalog loaded in a real Codex/Claude Code chat. Record those separately. No new execution worker, permissions, acceptance chores, task per iteration, transcript capture, commit or push.

## Delivered in 0.8.0 / workflow 1.6.0

- Shared MCP guidance and both generated client skills now describe recovering intent, reusing a change/approach/claim, reassessing on relevant drift, and checkpointing meaningful results, failed approaches and next steps. `get_workflow` exposes the loop protocol and required tool/field contract; it explicitly requires checking the actual client catalog rather than treating advertised support as verification.
- Native session state uses private per-session files and atomic writes under a cooperative lock, preserving shared legacy state as read-only fallback. Stop suppression is persisted before returning a reminder. It survives repeated calls, continuation prompts, helper process restarts and recovery until a checkpoint lands. State and pending/conflict checks are scoped to the native session. Delayed Stop/Interrupt events cannot roll back a newer local turn.
- Explicit per-session `mode --stop-policy observe` leaves all continuation to the runner. Default `checkpoint-once` retains the ordinary reminder. Neither emits `continue:false`; observe emits no Stop continuation fields. Mode survives resume and does not alter other chats.
- Startup/resume/compaction and the first prompt without successful startup recover full bounded context. Subsequent prompts opt into an explicitly incomplete refresh of at most 8 KB, including current assessment/claim state and bounded open requests. Old events remain compatible/full by default. Latest saved checkpoint remains available during recovery. No attempt/verification schema, UI redesign, runner, automatic work association or parking was added.
- Interrupt enqueues before sending, uses a short network budget, and installs a supported three-second Codex timeout. Existing managed labels/commands and all unrelated client settings/hooks are preserved.
